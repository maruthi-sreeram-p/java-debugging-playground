# Student Registry API

A small REST service that maintains the student records of a college department: create a student,
look one up, search the roll, update a record and remove a student who has left.

## Purpose

The Student Registry is the system of record for enrolled students. Other campus systems (the
attendance app, the examination portal) read student data from this API rather than keeping their
own copy, so the JSON contract below is expected to stay stable.

## Architecture

A single Spring Boot application with a conventional layered structure:

```
com.debuglab.studentregistry
├── StudentRegistryApplication      application entry point
├── controller/StudentController    HTTP layer, request/response mapping
├── service/StudentService          business logic, orchestration
├── repository/StudentRepository    Spring Data JPA repository
├── entity/Student                  JPA entity mapped to the `students` table
├── dto/StudentDto                  the object exposed over HTTP
├── mapper/StudentMapper            entity <-> DTO conversion
└── exception/                      domain exception + @RestControllerAdvice
```

The entity is never returned directly from a controller. Everything that crosses the HTTP boundary
is a `StudentDto`, so that the database schema can change without breaking API clients.

## Setup

### Prerequisites

* JDK 17 or newer on the `PATH`
* Maven 3.8+

No database server is required. The application uses an embedded in-memory H2 database that is
created at start-up and discarded at shutdown.

### Database setup

Nothing to install. On start-up Hibernate creates the `students` table from the entity mapping and
`src/main/resources/data.sql` seeds five students.

You can inspect the live database in your browser while the application is running:

* URL: <http://localhost:8080/h2-console>
* JDBC URL: `jdbc:h2:mem:studentdb`
* User: `sa`
* Password: *(leave blank)*

### Environment configuration

All configuration lives in `src/main/resources/application.properties`. The values that matter:

| Property | Default | Change it when |
|---|---|---|
| `server.port` | `8080` | port 8080 is already in use |
| `spring.datasource.url` | `jdbc:h2:mem:studentdb` | you want to point at a real database |
| `spring.datasource.username` / `.password` | `sa` / *(blank)* | you point at a real database — **put your own credentials here, they are not stored anywhere else** |
| `spring.jpa.hibernate.ddl-auto` | `create-drop` | you move to a persistent database |
| `logging.level.com.debuglab.studentregistry` | `DEBUG` | you want a quieter log |

There are no environment variables and no external services. Any credential you add is yours to
supply; the repository contains none.

## API endpoints

Base path: `/api/students`

| Method | Path | Description | Success status |
|---|---|---|---|
| `GET` | `/api/students` | List every student | `200 OK` |
| `GET` | `/api/students/{id}` | Fetch one student by id | `200 OK` |
| `GET` | `/api/students/search` | Search the roll. Both `name` and `department` are optional; supply either, both, or neither | `200 OK` |
| `POST` | `/api/students` | Create a student | `201 Created` |
| `PUT` | `/api/students/{id}` | Replace an existing student | `200 OK` |
| `DELETE` | `/api/students/{id}` | Remove a student | `204 No Content` |

### Student representation

```json
{
  "id": 1,
  "firstName": "Aarav",
  "lastName": "Sharma",
  "email": "aarav.sharma@campus.edu",
  "department": "CSE",
  "cgpa": 8.4
}
```

`firstName`, `lastName` and `email` are mandatory on write; `email` must be a valid address.
`department` and `cgpa` are optional. `id` is generated by the server and must not be sent by the
client.

### Expected functionality

**List every student**

```bash
curl http://localhost:8080/api/students
```

**Fetch one student**

```bash
curl http://localhost:8080/api/students/1
```

Returns the student, or `404 Not Found` with a JSON error body if the id does not exist.

**Search**

```bash
curl "http://localhost:8080/api/students/search?department=CSE"
curl "http://localhost:8080/api/students/search?name=aar"
curl "http://localhost:8080/api/students/search?name=aar&department=CSE"
curl "http://localhost:8080/api/students/search"
```

`name` matches part of the first or last name, case-insensitively. `department` is an exact match.
With no parameters the search returns the whole roll.

**Create a student**

```bash
curl -X POST http://localhost:8080/api/students \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Nisha","lastName":"Verma","email":"nisha.verma@campus.edu","department":"CSE","cgpa":8.8}'
```

Responds `201 Created` with the stored student, including the generated `id`. The stored record must
be identical to what was sent, so an immediate `GET /api/students/{id}` returns the same values.

**Update a student**

```bash
curl -X PUT http://localhost:8080/api/students/1 \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Aarav","lastName":"Sharma","email":"aarav.sharma@campus.edu","department":"IT","cgpa":8.6}'
```

**Delete a student**

```bash
curl -X DELETE http://localhost:8080/api/students/5
```

Responds `204 No Content`, or `404 Not Found` if the student does not exist.

### Error format

```json
{
  "timestamp": "2026-01-01T10:00:00",
  "status": 404,
  "error": "Not Found",
  "message": "Student not found with id 99"
}
```

Validation failures return `400 Bad Request` with a `fields` object naming each rejected field.
