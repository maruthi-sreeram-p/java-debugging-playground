# Order Service

A small e-commerce order service. It records who ordered what, at what price, where it should be
shipped, and lets a line be removed from an order before it is dispatched.

## Purpose

This service owns the order graph. An order is not a flat row — it belongs to a customer, contains a
list of line items, and optionally carries a shipping address. Keeping those four objects correctly
connected to each other, in memory *and* in the database, is the whole job of this service.

## Architecture

```
com.debuglab.orders
├── OrderServiceApplication
├── controller/
│   ├── OrderController             place, read, remove a line, and a raw graph endpoint
│   └── CustomerController          a customer's order history
├── service/OrderService            builds the order graph and maps it to DTOs
├── repository/
│   ├── CustomerRepository
│   ├── OrderRepository
│   └── OrderItemRepository
├── entity/
│   ├── Customer                    has many Orders
│   ├── Order                       belongs to a Customer, has many OrderItems,
│   │                               has at most one ShippingAddress
│   ├── OrderItem                   belongs to an Order
│   └── ShippingAddress             created fresh for each order that supplies one
├── dto/                            request and response shapes
└── exception/                      NotFoundException + @RestControllerAdvice
```

**This service owns its schema.** The tables are generated from the entity mappings on every start
(`ddl-auto=create-drop`) and `data.sql` then loads three customers. That is a deliberate choice for a
greenfield service and it means the mappings are the single source of truth — what you declare in the
entity classes is literally what the database becomes. Look at the generated tables if you ever want
to know what a mapping actually did.

## Setup

### Prerequisites

* JDK 17 or newer
* Maven 3.8+
* Docker Desktop (or any Docker engine with Compose v2)

### Database setup

```bash
docker compose up -d
```

MySQL is published on **host port 3307** so it cannot clash with a MySQL you already run on 3306.
The application creates its own tables at start-up; the container only provides an empty `ordersdb`
schema.

Open a shell against it whenever you want to see what is really stored:

```bash
docker exec -it debuglab06-mysql mysql -uroot -prootpw ordersdb
```

```sql
SHOW TABLES;
SELECT * FROM orders;
SELECT * FROM order_items;
```

Reset everything:

```bash
docker compose down -v && docker compose up -d
```

### Environment configuration

| Property | Value | Notes |
|---|---|---|
| `spring.datasource.url` | `jdbc:mysql://localhost:3307/ordersdb?...` | Host port from `docker-compose.yml` |
| `spring.datasource.username` | `orderuser` | **Placeholder credential** from `docker-compose.yml` — replace if you use your own MySQL |
| `spring.datasource.password` | `orderpw` | As above |
| `spring.jpa.hibernate.ddl-auto` | `create-drop` | This service generates its own schema |

No environment variables, no secrets, no external services.

## API endpoints

| Method | Path | Description | Success |
|---|---|---|---|
| `POST` | `/api/orders` | Place an order | `201` |
| `GET` | `/api/orders/{id}` | Read an order | `200`, `404` |
| `GET` | `/api/orders/{id}/raw` | The full entity graph, for support staff | `200`, `404` |
| `GET` | `/api/customers/{id}/orders` | A customer's order history | `200`, `404` |
| `DELETE` | `/api/orders/{orderId}/items/{itemId}` | Remove one line from an order | `204`, `404` |

### Placing an order

```bash
curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{
        "customerId": 1,
        "items": [
          { "productName": "Mechanical Keyboard", "unitPrice": 4499.00, "quantity": 1 },
          { "productName": "Wireless Mouse",      "unitPrice": 1299.00, "quantity": 2 }
        ]
      }'
```

Response:

```json
{
  "id": 1,
  "orderNumber": "ORD-64276D20",
  "customerId": 1,
  "customerName": "Aarav Sharma",
  "status": "PLACED",
  "placedAt": "2026-01-01T10:00:00",
  "totalAmount": 7097.00,
  "items": [
    { "id": 1, "productName": "Mechanical Keyboard", "unitPrice": 4499.00, "quantity": 1, "lineTotal": 4499.00 },
    { "id": 2, "productName": "Wireless Mouse",      "unitPrice": 1299.00, "quantity": 2, "lineTotal": 2598.00 }
  ],
  "shippingAddress": null
}
```

`totalAmount` is the sum of every line total. `orderNumber` is generated by the server.

### An order with a shipping address

```bash
curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{
        "customerId": 2,
        "items": [ { "productName": "Monitor 24 inch", "unitPrice": 11999.00, "quantity": 1 } ],
        "shippingAddress": {
          "line1": "12 MG Road", "city": "Bengaluru", "state": "Karnataka", "pincode": "560001"
        }
      }'
```

The address is stored with the order and echoed back as a single formatted line. `shippingAddress`
is optional — an order without one is perfectly valid.

### Reading an order

```bash
curl http://localhost:8080/api/orders/1
```

Returns exactly what was stored, including every line item.

### Order history

```bash
curl http://localhost:8080/api/customers/1/orders
```

Every order that customer has placed.

### Removing a line

```bash
curl -i -X DELETE http://localhost:8080/api/orders/1/items/2
```

Responds `204`. The line is deleted and the order's `totalAmount` is recalculated from the lines that
remain.

### Raw graph

```bash
curl http://localhost:8080/api/orders/1/raw
```

Returns the order entity with everything hanging off it — used by support staff when they need to see
the full picture rather than the tidied-up DTO.

## Expected functionality

* An order read back is identical to the order that was placed: same customer, same lines, same
  total.
* `totalAmount` always equals the sum of the line totals, both when the order is placed and after a
  line is removed.
* Everything visible through the API is visible in the database, and vice versa — `SELECT * FROM
  order_items` and the `items` array in the response always agree.
* A customer's history contains every order they have placed.
* Removing a line removes the row.
